# Repository Governance

The Web Doctor contribution catalog is governed through Git pull requests. Publishing an internal npm contribution does not register it; only a merged catalog change can select it for a Web Doctor release.

## CODEOWNERS

`.github/CODEOWNERS` assigns the complete `/registry/` path to `@platform/web-doctor`. This covers:

- `registry/catalog.json`
- `registry/ownership.json`
- `registry/registry.lock.json`
- future generated registry snapshots or metadata under `registry/`

Contribution owner metadata identifies the team accountable for package content. It does not replace the platform review requirement in the Web Doctor repository.

## Required Check

Protect the default branch with the GitHub Actions check:

```text
Registry / validate
```

The check runs registry-focused tests, retrieves exact package tarballs from the configured internal npm registry with lifecycle scripts disabled, verifies integrity and provenance, validates package contents and fixtures, regenerates the contribution lock, and fails when generated bytes differ from the checked-in lock.

## Branch Protection

Configure the default branch to:

1. Require a pull request before merging.
2. Require at least one approving review from CODEOWNERS.
3. Dismiss stale approvals when catalog, ownership, lock, contract, or registry implementation files change.
4. Require `Registry / validate` to pass against the latest commit.
5. Require conversation resolution.
6. Prevent force pushes and branch deletion.
7. Restrict bypass permission to the platform emergency group and audit every bypass.

Platform approval applies to the exact pull-request commit. Updating a package version, integrity, source provenance, generated lock, ownership, lifecycle, compatibility, dependency, portal, or layer requires the check and approval again.

## Emergency Revert

Revert through a new pull request. Select the previously retained exact package version and integrity, regenerate the lock, run `Registry / validate`, and obtain fresh CODEOWNERS approval. Do not mutate catalog history or published packages.
